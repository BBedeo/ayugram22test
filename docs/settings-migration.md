# Перенос настроек при смене ключа подписи

Android не ставит APK с другой подписью поверх установленного, поэтому переход со старого
ключа (debug) на релизный идёт через удаление и новую установку. Чтобы настройки не
потерялись, приложение умеет сохранить их в файл и вернуть после переустановки.

## Что переносится

Файл `ExFullGram-settings-<дата>.json` в публичной папке «Загрузки»
(`app.exteraless.backup.MigrationBackup`):

- `nkmrcfg`, `mainconfig`, `themeconfig` и избранные стикеры — через
  `SettingsBackupHelper` (все настройки семейства `nkmrcfg`: NekoConfig, NaConfig,
  ExFullGram, пресеты, ghost-списки, локальные имена и т.д.);
- все остальные файлы настроек мода по семействам имён (`exfullgram_`, `exteraless_`, `oe_`,
  `neko…`, `video_external_subtitles`): профили аккаунтов, уведомления и так далее. Новые файлы
  с такими именами подхватываются сами; исключения перечислены в `MOD_PREFS_DENY`.

Не переносится: сессия Telegram, блокировка приложения, API-ключи и токены (файл лежит в общей
папке), данные Test Mode, состояние плагинов и сами файлы плагинов, шрифты, иконки, обои и темы.

## Выпуск

1. Переходный релиз (подпись старым ключом, версия `1.3.99`): в тексте релиза добавить
   `<!-- exfullgram:backup -->`. Лист обновления покажет карточку «Сохраните настройки».
2. Релиз с новым ключом: в тексте `<!-- exfullgram:resign -->` и версия `1.4.N`
   (`exFullNewKeyBaseCommits` в `TMessagesProj/build.gradle` = число коммитов первой сборки
   1.4). Старые установки откроют лист из трёх шагов: экспорт, скачивание APK в «Загрузки»,
   удаление старого приложения. Метку нужно оставлять во всех последующих релизах, пока
   пользователи не перешли, иначе старая установка получит обычный лист и установка упадёт на
   конфликте подписей.
3. Новая установка без аккаунта сама ищет файл в «Загрузки» и предлагает вернуть настройки
   (`RestoreBackupSheet`); запасной путь — «Выбрать файл».

Метки — HTML-комментарии, в тексте листа не показываются. Проверка: `scripts/check_migration.py`.
